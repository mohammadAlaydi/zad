# ADR-0010: CI/CD — GitHub Actions, EAS for mobile, Docker for API

- **Status:** Accepted
- **Date:** 2026-05-13
- **Deciders:** Engineering
- **Tags:** ops

## Context

No CI/CD today. EAS is configured ([eas.json](../../eas.json)) but the `production` profile is empty. The brief lists a comprehensive pipeline (typecheck, lint, test, bundle-size, audit, Docker build, smoke test, staging deploy, E2E, prod manual gate, post-deploy health, auto-rollback).

Two artefacts ship from this repo: a Node API container and EAS-built mobile binaries (IPA + AAB). They have different toolchains and different release rhythms, so the workflows are split.

## Decision

### Branching

- `main` is always deployable to staging.
- `release/*` branches are cut from `main` for mobile App Store / Play Store releases (which can't be continuously delivered).
- Feature work in `claude/*` or `user/*` branches → PR to `main`.

### Required PR checks (all PRs)

`.github/workflows/ci.yml`:

| Job                    | Runs on       | Trigger                  | Notes                                                                                                |
| ---------------------- | ------------- | ------------------------ | ---------------------------------------------------------------------------------------------------- |
| `setup`                | ubuntu-latest | always                   | pnpm install (cached)                                                                                |
| `typecheck-mobile`     | ubuntu-latest | mobile or shared changed | `pnpm --filter @zadpay/mobile exec tsc --noEmit`                                                     |
| `typecheck-api`        | ubuntu-latest | api or shared changed    | `pnpm --filter @zadpay/api exec tsc --noEmit`                                                        |
| `lint`                 | ubuntu-latest | always                   | `pnpm lint` (ESLint zero-warnings)                                                                   |
| `format`               | ubuntu-latest | always                   | `pnpm prettier --check`                                                                              |
| `test-mobile-unit`     | ubuntu-latest | mobile or shared changed | Vitest                                                                                               |
| `test-api-unit`        | ubuntu-latest | api or shared changed    | Vitest, no containers                                                                                |
| `test-api-integration` | ubuntu-latest | api or shared changed    | Vitest + Testcontainers (Postgres, Redis)                                                            |
| `audit`                | ubuntu-latest | always                   | `pnpm audit --audit-level=high`                                                                      |
| `docker-build`         | ubuntu-latest | api changed              | `docker build apps/api` — smoke import + `/health/live`                                              |
| `mobile-bundle-size`   | ubuntu-latest | mobile changed           | `expo export --platform android --dump-sourcemap` + size report; **fails** if Hermes bytecode > 6 MB |
| `openapi-diff`         | ubuntu-latest | api changed              | regenerate OpenAPI, diff vs. `docs/openapi.json`, fail if breaking                                   |

- All checks **required** for merge. No bypasses except documented emergency procedure (which still requires a follow-up PR within 24h).

### Mobile artefact pipeline

`.github/workflows/mobile-release.yml`:

| Stage                    | Trigger                                        | Action                                                         |
| ------------------------ | ---------------------------------------------- | -------------------------------------------------------------- |
| `eas-preview`            | PR labelled `preview-mobile` or push to `main` | `eas build --profile preview --platform all --non-interactive` |
| `eas-production-ios`     | tag matches `mobile-v*`                        | `eas build --profile production --platform ios`                |
| `eas-production-android` | tag matches `mobile-v*`                        | `eas build --profile production --platform android`            |
| `eas-submit-ios`         | post-build, gated                              | `eas submit --platform ios` (TestFlight first)                 |
| `eas-submit-android`     | post-build, gated                              | `eas submit --platform android --track internal`               |
| `upload-sourcemaps`      | post-build                                     | Sentry CLI uploads with release = git SHA                      |

[eas.json](../../eas.json) updates needed:

- Real `production` profile: distribution `store`, autoIncrement `true` (build number), per-platform credentials referenced by EAS-managed secrets.
- A `preview-api-staging` profile that points `EXPO_PUBLIC_API_BASE_URL` to staging.
- A `preview-api-prod` profile for App Store / Play Store smoke testing pre-release.

API base URL is read from `expoConfig.extra.apiBaseUrl` at runtime, injected per profile via EAS env. Mobile **never** has a hardcoded URL.

### API artefact pipeline

`.github/workflows/api-release.yml`:

| Stage                | Trigger         | Action                                                                                               |
| -------------------- | --------------- | ---------------------------------------------------------------------------------------------------- |
| `build-image`        | merge to `main` | multi-stage `docker build`, tag `ghcr.io/zadpay/api:{git-sha}`                                       |
| `push-image`         | post-build      | push to GHCR                                                                                         |
| `deploy-staging`     | post-push       | rolling update on the staging cluster (kustomize or Helm; deployment infra out of scope of this ADR) |
| `smoke-staging`      | post-deploy     | curl `/health/ready` × 5 with 5 s spacing; fail if any non-200                                       |
| `e2e-staging`        | post-smoke      | Maestro flows targeting staging mobile preview (manual approval gate optional)                       |
| `promote-production` | manual approval | retag `:prod-{git-sha}` and deploy to prod cluster                                                   |
| `smoke-production`   | post-deploy     | same as staging                                                                                      |
| `auto-rollback`      | smoke fail      | redeploy `:prod-previous`                                                                            |

### Dockerfile shape (`apps/api/Dockerfile`)

```Dockerfile
# ── build ──────────────────────────────────────────────
FROM node:20-alpine AS build
RUN corepack enable && corepack prepare pnpm@9 --activate
WORKDIR /repo
COPY pnpm-lock.yaml pnpm-workspace.yaml package.json ./
COPY apps/api/package.json apps/api/
COPY packages packages
RUN pnpm install --frozen-lockfile --filter '@zadpay/api...'
COPY apps/api apps/api
RUN pnpm --filter @zadpay/api exec prisma generate
RUN pnpm --filter @zadpay/api run build

# ── prune ──────────────────────────────────────────────
FROM node:20-alpine AS prune
RUN corepack enable && corepack prepare pnpm@9 --activate
WORKDIR /repo
COPY --from=build /repo/pnpm-lock.yaml /repo/pnpm-workspace.yaml /repo/package.json ./
COPY --from=build /repo/apps/api/package.json apps/api/
COPY --from=build /repo/packages packages
RUN pnpm install --frozen-lockfile --prod --filter '@zadpay/api...'

# ── final ──────────────────────────────────────────────
FROM gcr.io/distroless/nodejs20-debian12:nonroot AS final
WORKDIR /app
COPY --from=prune /repo/node_modules /app/node_modules
COPY --from=prune /repo/apps/api/node_modules /app/apps/api/node_modules
COPY --from=prune /repo/packages /app/packages
COPY --from=build /repo/apps/api/dist /app/apps/api/dist
COPY --from=build /repo/apps/api/prisma /app/apps/api/prisma
ENV NODE_ENV=production
USER nonroot
EXPOSE 3000
CMD ["apps/api/dist/server.js"]
```

- Distroless final image: no shell, no apk, no anything except Node + the app. Smaller and harder to exploit.
- `USER nonroot`: process never runs as root.
- Image size target: < 150 MB (brief requirement). Distroless gets us under it.
- The **worker** process (BullMQ) shares the image; deployed as a separate Kubernetes Deployment with `CMD ["apps/api/dist/worker.js"]` override.

### docker-compose for local dev (root `docker-compose.yml`)

Postgres + Redis only. The API runs on the host with hot reload (`pnpm --filter @zadpay/api dev`). docker-compose is for backing services, not for running the app.

### Secrets in CI

- EAS credentials, npm token (none — we don't publish), Sentry auth token, GHCR token, K8s deploy key: all in repo secrets.
- Production env vars: live in the cluster's secret manager, never in CI logs. CI only triggers the deploy; the cluster reads its own secrets.

### Release notes

Conventional Commits enforced by `commitlint` in a pre-commit hook + a CI check. `release-please` generates `CHANGELOG.md` on merge to `main` (mobile and API have separate changelogs because they release on different cadences).

## Consequences

**Positive**

- Bad code can't reach `main`. Bad images can't reach prod (smoke + manual gate).
- Source maps in Sentry land for every release; production stack traces are debuggable.
- Same Dockerfile for API and worker; same image used everywhere.

**Negative**

- Initial setup (EAS production profile, GHCR auth, K8s deploy keys, Maestro Cloud account) is real ops work. We pay it once.

**Neutral / accept**

- We don't auto-deploy mobile to stores. App Store / Play Store releases require human eyes; trying to fully automate is more pain than value.

## Alternatives considered

1. **CircleCI / GitLab CI / Buildkite.** All fine. GitHub Actions is right here because the code is on GitHub and the action ecosystem (especially Expo's actions) is rich.
2. **Bazel for monorepo builds.** Real wins at >50 packages. Not here.
3. **EAS Update for OTA only (no native binary releases).** Tempting but a fintech app needs vetted store releases for crash + permission + native dep changes. EAS Update for in-cycle JS-only fixes, store release for everything else.

## Rollout

PR sequencing (final ones in the slice):

- PR-A: `.github/workflows/ci.yml` (typecheck, lint, test gates).
- PR-Late: `.github/workflows/api-release.yml`, `mobile-release.yml`, Dockerfile, docker-compose, real EAS profiles, Sentry source map upload.

## Revisit when

- Build times exceed 15 minutes → cache strategy + selective filters (`@zadpay/api...{HEAD~1}` style).
- We need preview deploys per PR (a real "ephemeral environment" workflow) → introduce Crossplane or Vercel-style PR previews for the API.
